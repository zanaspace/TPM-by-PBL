Module 7.1

The Anatomy of a World-Class Bug Report

Engineers hate ambiguous bug tickets like: "The app crashed when I clicked checkout." A Technical PM provides full diagnostic telemetry so the bug can be reproduced in 60 seconds:

📱

1. Environment & Context

OS version (iOS 17.4), device model (iPhone 15 Pro), App build number (#4092), staging vs production URL, and user correlation ID.

👣

2. Steps to Reproduce (STR)

Numbered, deterministic steps. Exactly what buttons were clicked, what data was input into which fields, and network state.

🔍

3. Expected vs Actual & Logs

Expected HTTP status & UI state vs. Actual HTTP 500 error code, Sentry stack trace snippet, and response payload.

Module 7.3

Root Cause Analysis: The 5 Whys Framework

When an outage is resolved, the TPM coordinates a blameless post-mortem. Asking "Why" 5 consecutive times drills past superficial symptoms to uncover systemic architectural flaws:

Why 1?
Why did customers get charged twice during checkout?

Because the web app sent two simultaneous HTTP requests to the payment endpoint.

Why 2?
Why did the web app send two requests?

Because the "Pay Now" button did not disable on the first tap, and the user double-clicked.

Why 3?
Why did the backend accept both identical requests?

Because the payment service had no distributed lock or idempotency check on duplicate order IDs.

Why 4?
Why was idempotency not implemented?

Because the payment PRD lacked non-functional requirements specifying network retry protection.

Why 5? (ROOT CAUSE)
Why did the PRD lack idempotency specs?

Because our engineering review process did not require an architecture sign-off checklist for financial transactions.

Module 7.4: Real-World Public Product Case Studies

Case Studies: DoorDash & Amazon Outages

DoorDash Inc.

How a Single Slow Database Query Froze 500k Food Orders

During a high-traffic Sunday football rush, a third-party coupon validation API slowed down from 50ms to 2,000ms.

The Cascading Failure

Connection Pool Saturation

Because the checkout service waited 2 full seconds per coupon check, open database connection pools filled to 100%. Subsequent orders queued and timed out.

The TPM Solution

Circuit Breaker Pattern

The TPM introduced a Circuit Breaker (Netflix Hystrix pattern): if the coupon API fails or takes > 300ms for 5 consecutive requests, the circuit "trips". Orders bypass coupon validation instantly and succeed!

Amazon Web Services

The DynamoDB US-EAST-1 Metadata Outage

A brief network hiccup caused metadata storage servers to renew leases simultaneously, hammering internal DNS servers with a "thundering herd" effect.

Thundering Herd Problem

Simultaneous Reconnection

When millions of servers attempt reconnection at the exact same millisecond, the recovery traffic is 10x higher than regular peak traffic!

The Fix

Exponential Backoff with Jitter

Clients must wait random intervals: wait = min(max_backoff, base * 2^attempt) + random_jitter so reconnection requests spread across several minutes.

Standard Bug Report with Reproduction Steps

Find or simulate a realistic production defect in your chosen case study product. Write a comprehensive Bug Report:

  1. Title & Severity Classification: Explicit P0–P3 tag with blast radius.
  2. Environment Details: OS, client version, user session context.
  3. Numbered Steps to Reproduce (STR): Clear, deterministic steps.
