Module 1.1

Why Technical Product Management?

In non-technical product management, you focus on "What problem to solve and why". In Technical Product Management (TPM), you must also deeply understand "How the system operates, where technical constraints exist, and how data moves across services".

🎯 The TPM Mission in PCIP

As a Technical PM, you don't write production code all day, but you must be able to:

  • Speak fluent engineering: Understand APIs, databases, latency, caching, and CI/CD.
  • Identify technical risks early: Anticipate database bottlenecks and API rate limits before launch.
  • Evaluate trade-offs: Balance technical debt vs speed-to-market.
  • Write technical PRDs: Specify data models, error handling, and API payloads with precision.

💡 Key Mindset Shift

A user says: "The app feels slow when I search for songs."

Generalist PM View:

"Let's add a loading spinner and tell users it's searching."

Technical PM View:

"Is the search hitting Postgres with an unindexed LIKE %query% query? Should we introduce an Elasticsearch cluster or edge-cache frequent queries with Redis?"

Module 1.2

The Triad: TPM vs. Generalist PM vs. Engineering Manager (EM)

Understanding where your role starts and ends is essential for seamless team collaboration.

Dimension Generalist Product Manager (PM) Technical Product Manager (TPM) Engineering Manager (EM) / Tech Lead
Primary Focus User experience, market fit, business model, go-to-market. System capabilities, platform scale, API contracts, technical feasibility. Code quality, system architecture implementation, team hiring & mentoring.
Key Question "What should we build and why?" "How will the system support this at scale and what are the dependencies?" "How do we write clean code and ship this sprint on time?"
Primary Artifact Feature PRD, User Personas, Wireframes, Business Canvas. Technical PRD, API Specifications, Data Flow Diagrams, Non-functional specs. Architecture Design Document (RFC), Pull Requests, Sprint Tasks.
Key Stakeholders Marketing, Sales, Design, Executive leadership. Core Engineers, Data Engineers, DevOps, 3rd Party API Partners. Software Developers, QA Engineers, SREs.

Module 1.4: Real-World Public Product Case Studies

Case Studies: Uber & Spotify Technical Breakdown

Uber Technologies

How Uber Works Under The Hood (TPM Breakdown)

Uber is not just an app; it is a real-time distributed geospatial dispatch platform handling millions of concurrent trips.

Frontend (Clients)

Rider & Driver Mobile Apps

  • Rider App: Native iOS/Android with lightweight Mapbox/Google Maps rendering.
  • Driver App: Emits high-frequency GPS ping every 4 seconds over persistent WebSockets.
  • TPM Consideration: Network drops in tunnels or elevators must not crash the active trip state.
Backend Services

Dispatch & Geolocation Engine

  • Geospatial Index (H3): Uber partitions earth into hexagonal cells (H3 index) to compute proximity in microseconds.
  • Trip Dispatch Service: Matches closest rated drivers using Dijkstra routing algorithms.
  • Surge Pricing Engine: Reads demand-to-supply ratio in hexagonal cells.
Data Stores

High-Throughput Storage

  • Redis: Keeps transient driver locations with 10-second TTL.
  • Docstore (MySQL on steroids) & Schemaless: Stores trips, rider profiles, receipts.
  • Apache Kafka: Streams every tap, location ping, and payment event for real-time analytics.
External APIs

Third-Party Ecosystem

  • Google Maps / Mapbox API: Road traffic speed and turn-by-turn guidance.
  • Stripe / Braintree / Apple Pay: Pre-authorizing funds and capturing payment on trip end.
  • Twilio: Masked phone numbers so rider and driver talk safely.
🎓 TPM Lesson from Uber: When an Uber passenger requests a ride, the system does not poll every car worldwide. The TPM designs around geospatial boundaries (hex cells), fails gracefully if SMS providers lag, and monitors API latency strictly below 200ms.
Spotify AB

How Spotify Streams Music Instantly (TPM Breakdown)

When you press "Play", how does music start in under 200 milliseconds without buffering?

Frontend (Playback)

Spotify Desktop, Mobile & Web Players

  • Local Cache: Spotify stores recently played audio chunks encrypted on your phone disk.
  • Predictive Buffering: Starts loading the next song in your playlist 10 seconds before the current song finishes.
Backend Services

Audio Transcoding & Recommendation

  • Audio Encoding Pipeline: Converts master WAV files into multiple Ogg Vorbis/AAC bitrates (96kbps, 160kbps, 320kbps).
  • Discover Weekly: Collaborative filtering algorithms (matrix factorization) computing playlist graphs.
Storage & CDN

Edge Content Delivery

  • Content Delivery Network (CDN): Audio files are cached in server clusters physically near the user (Cloudflare / Fastly).
  • Cassandra: Handles billions of user library records and playlist tracks.
APIs & Integrations

Ecosystem & Rights

  • Spotify Web API: Public endpoints for developers (e.g. GET /v1/tracks/{id}).
  • Royalty Calculation Engine: Aggregates every play count >30s to pay labels and artists.
🎓 TPM Lesson from Spotify: Audio files are never fetched directly from a SQL database. The TPM decouples "Metadata" (artist name, track title in a fast DB) from "Binary Media" (the MP3/Ogg files stored on CDN edge servers).

Classroom Prompts

Saturday Workshop Discussion Questions

Question 1: If Twilio goes down during an Uber rider login, what should the app do?

TPM Solution: Never let a third-party failure lock users out entirely. The system should implement a fallback channel: offer WhatsApp verification, email magic links, or switch dynamically to a secondary backup SMS gateway (like Infobip or MessageBird). The client should display a clear retry timer rather than an ambiguous crash.

Question 2: Why doesn't Spotify just query Postgres whenever a user taps Play?

TPM Solution: Relational databases are optimized for transactional ACID queries (e.g. updating an account balance), not streaming binary audio files (BLOBs) to 500 million listeners. Storing audio in Postgres would exhaust memory, saturate disk I/O, and cause catastrophic connection limits. Audio is stored on Object Storage (S3) and replicated across CDN edges.

Question 3: How does a TPM measure whether a backend API is healthy?

TPM Solution: The four golden signals: Latency (P95 and P99 response times), Traffic (Requests Per Second / RPS), Errors (HTTP 5xx rate), and Saturation (CPU and memory utilization on the host servers).
