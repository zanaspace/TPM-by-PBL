Module 3.1

What is an API to a Technical Product Manager?

An Application Programming Interface (API) is a contract between two software systems. Just as a UI is an interface for humans (buttons, inputs), an API is an interface for computers (endpoints, JSON parameters, and return codes).

📡

REST (Representational State Transfer)

Stateless, resource-based over HTTP. Every resource is identified by a URI (e.g. /v1/customers/cus_123) and manipulated using standard HTTP verbs.

🔔

Webhooks (Reverse APIs)

Instead of your app asking "Did the payment succeed?" 50 times a minute (polling), the payment provider calls your webhook URL instantly when the event occurs (Pub/Sub push).

🛡️

Idempotency Keys

A safety token sent in headers. If a user hits "Pay" twice due to poor network, the server recognizes the identical key and ensures only one transaction occurs.

Module 3.2

HTTP Verbs & Status Codes Every TPM Must Memorize

HTTP Verbs (Methods)

  • GET /orders: Retrieve resources (Safe & Idempotent; never modifies state).
  • POST /orders: Create a brand new resource.
  • PUT /orders/123: Replace the entire resource representation.
  • PATCH /orders/123: Partially update specific fields (e.g. update status to "Shipped").
  • DELETE /orders/123: Remove the resource.

HTTP Status Code Families

  • 2xx Success: 200 OK (Read), 201 Created (Resource added), 204 No Content (Deleted).
  • 4xx Client Errors: 400 Bad Request (Malformed JSON), 401 Unauthorized (No token), 403 Forbidden (Wrong permissions), 404 Not Found, 429 Too Many Requests (Rate limit).
  • 5xx Server Errors: 500 Internal Error (Crash in code), 502 Bad Gateway, 503 Service Unavailable (Overloaded server), 504 Gateway Timeout.
Module 3.3: Real-World Public Product Case Studies

Case Studies: Stripe & Google Maps API

Stripe, Inc.

How Stripe Designed the Benchmark for Developer Experience

Stripe became a $90B company because developers loved their 7 lines of API code. Here is how their API contracts are structured.

Endpoint Design

Predictable Resource URLs

  • POST /v1/payment_intents: Initiates a payment lifecycle.
  • GET /v1/payment_intents/:id: Retrieves current status.
  • Every object returns standard JSON with an id prefix (e.g. pi_3MtwBwLkdIwHu7ix).
Resilience

The Idempotency Key

  • Header: Idempotency-Key: 9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d.
  • If the network drops mid-request and the client retries, Stripe returns the original cached response instead of charging the credit card twice!
Async Communication

Webhooks with HMAC Signatures

  • When asynchronous events occur (e.g. 3D-Secure bank approval 10 minutes later), Stripe pushes a JSON payload to your server.
  • Signed with Stripe-Signature header so hackers cannot fake successful payment notices.
TPM Lesson

Machine-Readable Error Codes

  • Stripe errors return structured codes: {"type": "card_error", "code": "card_declined", "decline_code": "insufficient_funds"}.
  • This allows TPMs to write explicit UI flows: "Show a prompt asking user to try another card."
Google Maps Platform

High-Throughput Geospatial Routing API

Google Maps processes billions of queries daily. Learn how they manage query params, quotas, and caching.

Query Design

Parameter-Driven Endpoints

  • GET https://maps.googleapis.com/maps/api/directions/json?origin=Lagos&destination=Ibadan&key=AIzaSy...
  • Uses HTTP GET because the query is idempotent and read-only.
Rate Limiting

QPS & Quota Management

  • Enforces Queries Per Second (QPS) limits per API Key.
  • Returns 429 Too Many Requests with OVER_QUERY_LIMIT when an app exceeds its billing tier.
Performance

Coordinate Snapping & Polyline Compression

  • Instead of sending 50,000 latitude/longitude GPS points (which would be 2MB JSON), it encodes routes into compressed 15KB polyline strings.
TPM Lesson

Billable Unit Awareness

  • A TPM must design client debouncing: do not fire an Autocomplete API call on every single keystroke; wait 300ms after the user stops typing to save thousands of dollars!
